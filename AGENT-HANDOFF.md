# Продолжение разработки

## Начать здесь
В корне публичного репозитория код находится в vacancy-voice-source.zip. Распаковать, перейти в vacancy-voice. Читать AGENTS.md, docs/SPEC.md, docs/SUBMISSION.md, docs/QA.md. Актуальное поведение — v5; исторические разделы PROCESS/QA не переопределяют SPEC.

Node 22.13+, npm install (lockfile входит в архив), собственный Groq Free ключ в .dev.vars по .env.example. Значения секретов не печатать, не коммитить. npm run dev; npx tsc --noEmit; npm run build. Production развёрнут в Cloudflare Workers. Изменение кода требует пересборки; просмотрщик прототипа не вводит ключ.

## Владельцы ответственности
- lib/vacancy.ts: 4 вопроса, схемы и формат итогового текста.
- app/page.tsx: переходы, запись, черновик вкладки, редактор, отмена и финальная анимация.
- lib/earcons.ts: локальные звуки, без сети.
- app/globals.css: высота окна, компоненты/токены, reduced motion, адаптация.
- lib/groq.ts: критерии полноты, реальный вызов модели, ошибки, базовая защита запросов.
- app/api/{transcribe,analyze,generate}/route.ts: контракты и серверная валидация.

## Не нарушать
Четыре исходных смысла и порядок. Модель не выбирает следующий экран. Прогресс определяется confirmed конкретного шага. Один operation id владеет всей цепочкой; отменённые/поздние ответы не перезаписывают состояние. Не добавлять сведения, не названные пользователем. Не показывать успех до успешного ответа сервера. Не заменять модель имитацией при ошибках. Не подключать платёжные сервисы/тарифы. Не публиковать личные тестовые ответы и аудио.

## Проверка изменения
1. Записать новый критерий в SPEC до изменения поведения.
2. Проверить типы и сборку.
3. Пройти затронутые состояния по TEST-CASES.md. Для модели — реальные вызовы на синтетических данных, сохранить наблюдения с датой. Для звука/микрофона — ручная проба человека.
4. Проверить обычный экран, предупреждение, редактор и результат при 1280×720 и 375×667; вся страница не прокручивается, основные кнопки видны. При увеличении/малой высоте важнее доступность, чем запрет прокрутки.
5. Обновить документацию/презентацию, упаковать исходники без .dev.vars, node_modules, .wrangler и журналов. Проверить архив и итоговый публичный адрес. Не отправлять работодателю без поручения автора.

## Следующие приоритеты после тестового
Реальные пользовательские пробы, качество модели на корпусе ответов, браузерная матрица, глобальные квоты/защита, политика хранения и промышленная эксплуатация. Не начинать с ещё одной декоративной функции.
